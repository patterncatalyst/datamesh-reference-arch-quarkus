Setup & prerequisites

Running the reference, start to finish.

From a bare workstation to a running Quarkus data mesh — JDK, Maven, the Quarkus CLI, and a Docker Compose stack for Kafka, Postgres, and observability.

Required tooling

  • SDKMAN — manages JDK 25, Maven 3.9.x, JBang, and the Quarkus CLI
  • Quarkus CLI — quarkus create, quarkus dev
  • Docker and Docker Compose — the v2 CLI plugin, not podman
  • Camel CLI & the Camel MCP server — Camel-on-Quarkus route prototyping and validation
  • Demo command-line tools — curl, jq, grpcurl, and kcat (Fedora: sudo dnf install kcat); demos/walkthrough.sh checks for them before it starts
  • The Quarkus Agent MCP server — dev-loop tooling for Claude Code (project create, skills, docs search, logs)

Installing the toolchain via SDKMAN

curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 25-tem
sdk install maven 3.9.9
sdk install quarkus

Container engine sizing

Everything here runs on one Docker engine: the Compose stack, Dev Services and Testcontainers during mvn verify, the Mandrel builder image for native builds, and minikube, which runs as a container under its Docker driver. How much of the machine that engine can use depends on how Docker is installed:

  • Docker Engine on Linux runs directly on the host. It uses all host CPUs and memory and stores images under /var/lib/docker on the host disk, so there is nothing to size.
  • Docker Desktop (macOS, Windows, Linux) runs the engine inside a VM with a fixed CPU count, memory limit, and virtual disk. The defaults are too small for the full path.
WorkloadCPUsMemoryEngine disk
Compose stack, dev mode, mvn verify, native build 816 GB100 GB
Everything above plus minikube at the bootstrap defaults (24 GB) 8+28 GB200 GB

Disk runs out first. On a Docker Desktop VM with a 64 GB disk, both the native-build demo and the Ollama image pull for the AI service tests failed with no space left on device. With Docker Engine, budget host memory the same way: at least 32 GB for the minikube path, leaving room for the OS, IDE, and browser.

Option A: Docker Engine on Linux (no VM)

Install Docker Engine and the Compose plugin from docs.docker.com/engine/install for your distribution, then enable it and point the CLI at it: 

sudo systemctl enable --now docker.socket docker.service
sudo usermod -aG docker "$USER"     # log out and back in afterwards
docker context use default          # if Docker Desktop was installed before
docker info | grep -E 'CPUs|Total Memory|Docker Root Dir'

If Docker Desktop is also installed, stop it (docker desktop stop) so only one engine is in use. The two engines keep separate images and volumes; switch back with docker context use desktop-linux.

Option B: resize Docker Desktop

In the dashboard: Settings → Resources → Advanced, set CPUs, Memory, and Virtual disk limit, then Apply & restart. On Windows with the WSL 2 backend, CPU and memory come from %UserProfile%\.wslconfig (processors=, memory=, then wsl --shutdown) instead of these settings.

Without the dashboard, edit settings-store.json while Docker Desktop is stopped. It lives at ~/.docker/desktop/ on Linux, ~/Library/Group Containers/group.com.docker/ on macOS, and %APPDATA%\Docker\ on Windows. The sizes are in MiB: 

docker desktop stop                  # Docker Desktop 4.37+; otherwise quit from the tray
cd ~/.docker/desktop                 # Linux path; see above for macOS/Windows
cp settings-store.json settings-store.json.bak
jq '.Cpus=8 | .MemoryMiB=28672 | .DiskSizeMiB=204800' settings-store.json.bak > settings-store.json
docker desktop start

The virtual disk can grow but not shrink. Confirm the new limits from inside the VM: 

docker info | grep -E 'CPUs|Total Memory'
docker run --rm alpine:3.22 df -h /

Fitting minikube to the engine

scripts/bootstrap.sh starts minikube with 24 GB, 16 CPUs, and an 80 GB disk. minikube cannot request more CPUs or memory than the engine has, so override the defaults to fit. On an 8-CPU Docker Desktop VM: 

MINIKUBE_CPUS=8 ./scripts/bootstrap.sh
# also available: MINIKUBE_MEMORY (default 24g), MINIKUBE_DISK (default 80g)

Bootstrap

The local infrastructure — Kafka, Postgres, Apicurio, and the observability stack — runs via Docker Compose from the repo root. Copy the env template, bring the stack up, then start any service in dev mode: 

cp .env.example .env
docker compose up -d
cd examples/<service>
mvn quarkus:dev

Host ports come from .env. On Fedora and RHEL, the Cockpit web console listens on 9090, which .env.example assigns to Mimir; set MIMIR_PORT=19090 (or any free port) in .env before docker compose up.

For the Kubernetes substrate (Istio, KEDA, Strimzi, CloudNativePG on a local Kubernetes cluster — needed for the KEDA demos), run scripts/bootstrap.sh. See k8s/ for the manifests.

Verifying a service

mvn verify -f examples/pom.xml   # unit + integration tests, every service
mvn package -Pnative              # native build (GraalVM/Mandrel)
quarkus build --native            # equivalent, via the Quarkus CLI
./scripts/run-all-tests.sh        # single entrypoint for the full test suite
