Setup & prerequisites

Running the reference, start to finish.

From a bare workstation to a running Quarkus data mesh — JDK, Maven, the Quarkus CLI, and a Docker Compose stack for Kafka, Postgres, and observability.

Version matrix

Component Version Notes
Quarkus 3.39.5 Current latest stable (4.0.0 is Beta only)
JDK 25 (25-tem) Supported on Quarkus 3.39.x
Camel platform-aligned Imported via quarkus-camel-bom:3.39.5 — no standalone Camel version pin
langchain4j (Quarkiverse) 1.14.1 Watch for tool-calling API drift, especially against Ollama
Maven 3.9.x
Base images UBI (ubi10/openjdk-25) Multi-stage builder + runtime images
Container toolchain Docker / Docker Compose Not podman — see the lgtm-docker-stack skill

Required tooling

  • SDKMAN — manages JDK 25, Maven 3.9.x, JBang, and the Quarkus CLI
  • Quarkus CLI — quarkus create, quarkus dev
  • Docker and Docker Compose — the v2 CLI plugin, not podman
  • Camel CLI & the Camel MCP server — Camel-on-Quarkus route prototyping and validation
  • The Quarkus Agent MCP server — dev-loop tooling for Claude Code (project create, skills, docs search, logs)

Installing the toolchain via SDKMAN

curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 25-tem
sdk install maven 3.9.9
sdk install quarkus

Bootstrap

The local infrastructure — Kafka, Postgres, and the observability stack — runs via Docker Compose. Bootstrap scripts and the full examples/ tree ship in a later build step; once they land, bringing a service up will look like: 

docker compose up -d
cd examples/<service>
mvn quarkus:dev

Verifying a service

mvn verify                 # unit + integration tests
mvn package -Pnative        # native build (GraalVM/Mandrel)
quarkus build --native      # equivalent, via the Quarkus CLI
