Demos & examples

See every principle and capability, live.

Each demo is mapped 1:1 to a data-mesh principle — domain ownership, data as a product, self-serve platform, federated computational governance — and to the Quarkus capability it exercises. The runnable examples/ tree and demos/*.sh scripts ship in a later build step; this page tracks what's planned and will link to each one once it lands.

Planned demos by principle

Domain ownership & data as a product

Each domain service — order, inventory, payment, shipping, notification, review — owns its data, its API surface, and its operational lifecycle.

Domain ownership · Panache + REST

Order-service walking skeleton

Build, deploy, REST round-trip against a Panache-backed Postgres entity.

Domain ownership · gRPC

Cross-service gRPC

order-service calls inventory-service over quarkus-grpc. Proves domain isolation with clear API boundaries.

Data as a product · GraphQL

Federated read layer

A SmallRye GraphQL gateway stitches REST and gRPC data products into one composed query.

Self-serve platform

Self-serve platform · Kafka

Async spine (Reactive Messaging)

order-service publishes order.placed; notification-service consumes it via Quarkus Reactive Messaging.

Self-serve platform · KEDA

Scale-from-zero autoscaling

Kafka consumer-lag and HTTP-concurrency scaling for notification-service and the GraphQL gateway.

Self-serve platform · dev loop

Continuous testing & Dev Services

Live reload, continuous testing, and Testcontainers-backed Dev Services as a platform capability, not a chore.

Federated computational governance

Federated governance · Camel

Camel EIPs on Quarkus

Routes composing the mesh's messaging backbone — content-based routing, aggregation, and transformation between data products.

Federated governance · langchain4j + MCP

AI tool routes

A Camel route exposes an order-lookup tool over MCP; langchain4j drives it from a natural-language prompt.

Federated governance · OpenTelemetry

End-to-end tracing

A GraphQL query fans out across three data products; the trace lands with cross-service spans.

Quarkus vs. Spring Boot

One runnable Spring Boot twin service ships alongside its Quarkus counterpart for a real side-by-side comparison — startup time, memory footprint, and native-image build.

Running a demo (once available)

Demos will assume a local Docker Compose stack (Kafka, Postgres, the observability stack) is running. See setup & prerequisites for the toolchain. 

docker compose up -d
cd examples/<service>
mvn quarkus:dev
